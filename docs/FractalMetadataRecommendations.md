# Fractal Image Metadata Recommendations for ManpLab

## Executive Summary

This document provides recommendations for embedding fractal generation metadata into PNG and JPEG image files. The goal is to make fractal images self-documenting, enabling users to:
- Reproduce the exact fractal rendering
- Share parameters with other users
- Build searchable fractal libraries
- Preserve mathematical precision for deep zooms

## Recommended Metadata Strategy

### Core Philosophy: Dual-Layer Approach

1. **Application-Specific Layer**: Complete, machine-readable JSON for perfect reproduction
2. **Human-Readable Layer**: Standard properties for viewing in any image browser

---

## PNG Format Recommendations (Primary Format)

### Advantages for Fractal Applications
- ✅ Lossless compression preserves pixel-perfect detail
- ✅ Simple tEXt chunk API for custom metadata
- ✅ Reliable read/write cycle in Windows.Graphics.Imaging
- ✅ No length restrictions on text chunks
- ✅ Multiple tEXt chunks can coexist independently

### Recommended Property Mapping for PNG

#### Layer 1: Machine-Readable JSON Blob
**Property**: `/tEXt/ManpLabMetadata`
**Format**: Minified JSON (no whitespace)
**Purpose**: Complete parameter set for exact reproduction

**Example Content**:
```json
{"Software":"ManpLab","Version":"1.0.0","FractalFamily":"Classic Escape-Time","FractalName":"Mandelbrot Set","FractalType":"Mandelbrot","IterationMode":"Standard","CenterX":-0.5,"CenterY":0.0,"Zoom":1.0,"MaxIterations":512,"ColorPalette":"Classic","ImageWidth":1920,"ImageHeight":1080,"RenderTime":1.234,"Timestamp":"2024-01-15T10:30:45Z","DeepZoom":false,"JuliaC":null}
```

**Benefits**:
- Single property contains everything
- Easy to parse programmatically
- Extensible without breaking compatibility
- Can include computed values (render time, etc.)

#### Layer 2: Human-Readable Standard Properties

| Property Path | Example Value | Purpose |
|--------------|---------------|---------|
| `/tEXt/Software` | `"ManpLab v1.0.0"` | Identifies generating application with version |
| `/tEXt/Source` | `"https://github.com/markhassellsmith/ManpLab"` | **RECOMMENDED**: Source code repository for attribution |
| `/tEXt/Title` | `"Mandelbrot Seahorse Valley"` | User-friendly name |
| `/tEXt/Description` | `"Mandelbrot set centered at (-0.75, 0.1), zoom 1000x, 512 iterations"` | Human summary |
| `/tEXt/Author` | `"Mark Smith"` | Creator name (user who rendered) |
| `/tEXt/Copyright` | `"© 2024 Mark Smith"` | Copyright notice (user's copyright) |
| `/tEXt/Creation Time` | `"2024-01-15 10:30:45"` | Timestamp |
| `/tEXt/Comment` | `"Generated by ManpLab - Open source fractal explorer"` | Additional notes with attribution |

#### Layer 3: Optional Individual Parameters (for metadata browsers)

For applications that can't parse JSON, consider also storing key parameters individually:

| Property Path | Example Value | Note |
|--------------|---------------|------|
| `/tEXt/FractalType` | `"Mandelbrot"` | Redundant but browsable |
| `/tEXt/CenterX` | `"-0.7500000000"` | High precision string |
| `/tEXt/CenterY` | `"0.1000000000"` | High precision string |
| `/tEXt/Zoom` | `"1000.0"` | Scientific notation if needed |
| `/tEXt/MaxIterations` | `"512"` | Integer as string |
| `/tEXt/ColorPalette` | `"Classic"` | Palette name |
| `/tEXt/IterationMode` | `"Standard"` or `"Julia"` | Mode identifier |
| `/tEXt/JuliaCX` | `"-0.7"` | If Julia mode |
| `/tEXt/JuliaCY` | `"0.27015"` | If Julia mode |

**Trade-off**: More properties = more metadata overhead, but better compatibility with generic viewers.

## JPEG Format Recommendations (Secondary Format)

### Advantages for Fractal Applications
- ✅ Smaller file sizes (lossy compression)
- ✅ Better compatibility with web browsers and social media
- ✅ EXIF tags understood by most image viewers

### Challenges
- ❌ Lossy compression may introduce artifacts in gradients
- ❌ EXIF tags have fixed schemas and limited extensibility
- ❌ Custom metadata requires EXIF UserComment or XMP
- ❌ More complex property paths in Windows.Graphics.Imaging

### Recommended Property Mapping for JPEG

#### Layer 1: Machine-Readable via EXIF UserComment
**Property**: `/app1/ifd/exif/{ushort=37510}` (EXIF UserComment)
**Format**: JSON string with character code prefix
**Purpose**: Complete parameter set

**Implementation Note**: EXIF UserComment requires an 8-byte character code prefix. Use ASCII encoding:
```
[ASCII\0\0\0] + JSON string
```

**Example**:
```
ASCII   {"Software":"ManpLab","Version":"1.0.0",...}
```

#### Layer 2: Standard EXIF Tags

| Property Path | EXIF Tag | Example Value | Purpose |
|--------------|----------|---------------|---------|
| `/app1/ifd/{ushort=305}` | Software | `"ManpLab v1.0.0"` | Generator app with version |
| `/app1/ifd/{ushort=270}` | ImageDescription | `"Mandelbrot at (-0.75,0.1) 1000x zoom - https://github.com/markhassellsmith/ManpLab"` | Human summary with attribution |
| `/app1/ifd/{ushort=315}` | Artist | `"Mark Smith"` | Creator (user who rendered) |
| `/app1/ifd/{ushort=33432}` | Copyright | `"© 2024 Mark Smith. Generated by ManpLab"` | Copyright with software attribution |
| `/app1/ifd/exif/{ushort=36868}` | DateTimeDigitized | `"2024:01:15 10:30:45"` | Creation time |
| `/app1/ifd/{ushort=282}` | XResolution | `96` | DPI (display hint) |
| `/app1/ifd/{ushort=283}` | YResolution | `96` | DPI (display hint) |

#### Layer 3: Optional XMP Metadata (Advanced)

For maximum compatibility with professional tools, consider XMP:

| Property Path | Example Value | Purpose |
|--------------|---------------|---------|
| `/xmp/dc:title` | `"Mandelbrot Seahorse Valley"` | Dublin Core title |
| `/xmp/dc:description` | `"Mandelbrot set centered at (-0.75, 0.1)..."` | DC description |
| `/xmp/dc:creator` | `"Mark Smith"` | DC creator |
| `/xmp/xmp:CreatorTool` | `"ManpLab 1.0.0"` | Software |
| `/xmp/xmp:CreateDate` | `"2024-01-15T10:30:45Z"` | ISO 8601 timestamp |

**Note**: XMP is XML-based and more complex to write. Consider only if targeting professional workflows (Adobe products, etc.).

## Detailed Property Recommendations by Category

### 1. Essential Identification Properties

**Priority: CRITICAL**

These properties must be present in every saved image:

| Property | PNG Path | JPEG Path | Example | Rationale |
|----------|----------|-----------|---------|-----------|
| Software | `/tEXt/Software` | `/app1/ifd/{ushort=305}` | `"ManpLab v1.0.0"` | Identifies generator with version |
| Source URL | `/tEXt/Source` | `/app1/ifd/{ushort=270}` | `"https://github.com/markhassellsmith/ManpLab"` | **RECOMMENDED**: Attribution and source code link |
| Timestamp | `/tEXt/Creation Time` | `/app1/ifd/exif/{ushort=36868}` | `"2024-01-15 10:30:45"` | When created |
| Full Metadata | `/tEXt/ManpLabMetadata` | `/app1/ifd/exif/{ushort=37510}` | JSON blob | Complete params for reproduction |

### 2. Mathematical Parameters

**Priority: CRITICAL**

Required for reproducing the fractal:

| Parameter | Data Type | Precision | Example | Notes |
|-----------|-----------|-----------|---------|-------|
| FractalFamily | String | N/A | `"Classic Escape-Time"` | Browser folder/category (user-facing) |
| FractalName | String | N/A | `"Mandelbrot Set"` | Display name (user-facing) |
| FractalType | String | N/A | `"Mandelbrot"` | Internal registry key (technical) |
| CenterX | Double | 15-17 digits | `"-0.75000000000000"` | Complex plane real part |
| CenterY | Double | 15-17 digits | `"0.10000000000000"` | Complex plane imaginary part |
| ZoomFactor | Double | 15-17 digits | `"1000.0"` | Magnification level (UI: "Zoom:") |
| ViewWidth | Double | 15-17 digits | `"0.0139746244"` | Complex plane viewport width |
| ViewHeight | Double | 15-17 digits | `"0.0078607262"` | Complex plane viewport height |
| MaxIterations | Integer | N/A | `512` | Escape-time threshold |

**ViewWidth and ViewHeight Calculation:**
These values represent the dimensions of the complex plane visible in the rendered image:
```
ViewWidth = ImageWidth / (ZoomFactor × aspectRatioScale)
ViewHeight = ImageHeight / (ZoomFactor × aspectRatioScale)
```
They are useful for:
- Understanding the mathematical scale of the view
- Calculating pixel-to-complex-plane coordinate mappings
- Verifying reproduction accuracy
- Displaying technical information to users

**Deep Zoom Considerations**:
- For Zoom ≥ 1e10, standard double precision may be insufficient
- Consider storing as string with arbitrary precision: `"1.234567890123456789e+15"`
- Include `DeepZoom` boolean flag to indicate precision requirements
- May need to store intermediate BigNum representations

### 3. Rendering Parameters

**Priority: HIGH**

Affect visual appearance:

| Parameter | Example | Purpose |
|-----------|---------|---------|
| PaletteName | `"Classic"` | Color scheme name (UI: "Palette:") |
| IterationMode | `"Standard"` or `"Julia"` | Algorithm variant |
| ResolutionWidth | `1920` | Image pixel width |
| ResolutionHeight | `1080` | Image pixel height |
| ResolutionMegapixels | `2.07` | (Width × Height) / 1,000,000 |
| AutoScaleIterations | `true` | Whether max iterations auto-adjust with zoom |
| RenderTimeSeconds | `1.234` | Render duration in seconds |
| EscapePercentage | `87.3` | Percentage of pixels that escaped (optional) |

**Auto-Scale Iterations:**
When enabled, `MaxIterations` automatically increases as zoom level increases to maintain visual detail. The base `MaxIterations` value is still stored; `AutoScaleIterations` indicates whether the value was user-set or dynamically calculated.

**Escape Percentage:**
The percentage of pixels that reached the escape threshold. Useful for:
- Understanding the complexity of the rendered region
- Identifying areas of high detail (lower escape %) vs. simple regions (higher escape %)
- Performance analysis and optimization

### 4. Julia Set Parameters

**Priority: CRITICAL (if Julia mode)**

Only needed when IterationMode = "Julia":

| Parameter | Example | Purpose |
|-----------|---------|---------|
| JuliaCX | `-0.7` | Julia constant real part |
| JuliaCY | `0.27015` | Julia constant imaginary part |

### 5. Render Statistics

**Priority: MEDIUM**

Derived metrics providing insights into the render:

| Parameter | Data Type | Example | Derivation | Purpose |
|-----------|-----------|---------|------------|---------|
| ResolutionMegapixels | Double | `2.07` | (Width × Height) / 1,000,000 | Quick resolution reference |
| EscapePercentage | Double | `87.3` | (Escaped Pixels / Total Pixels) × 100 | Complexity indicator |
| RenderTimeSeconds | Double | `3.337` | ComputeTimeMs / 1000 | Performance metric |

**Use Cases:**
- **ResolutionMegapixels**: Enables filtering/sorting images by resolution without parsing width × height
- **EscapePercentage**: Indicates visual complexity; lower values = more detail/structure
- **RenderTimeSeconds**: Tracks computational cost; useful for benchmarking and optimization

### 6. User Attribution

**Priority: MEDIUM**

Optional but recommended for sharing:

| Property | PNG Path | JPEG Path | Example |
|----------|----------|-----------|---------|
| Author | `/tEXt/Author` | `/app1/ifd/{ushort=315}` | `"Mark Smith"` |
| Copyright | `/tEXt/Copyright` | `/app1/ifd/{ushort=33432}` | `"© 2024 Mark Smith"` |
| Title | `/tEXt/Title` | `/app1/ifd/{ushort=270}` | `"Seahorse Valley"` |
| Description | `/tEXt/Description` | `/app1/ifd/{ushort=270}` | `"Beautiful spirals..."` |
| Comment | `/tEXt/Comment` | `/app1/ifd/exif/{ushort=37510}` | `"My first deep zoom"` |
| **UserNotes** | `/tEXt/UserNotes` | `/app1/ifd/exif/{ushort=37510}` | `"Deep zoom series for art exhibition project"` |

**UserNotes Field**:
- Multi-line text box from Properties panel "Personal Notes"
- Generous character allowance (500+ characters recommended)
- Use case: Tag files for special projects, track exploration goals, mark favorites
- Example: `"Part of my seahorse valley exploration series. Testing iteration limits at this zoom level. Will use for conference presentation."`

### 7. Technical Details

**Priority: LOW**

Useful for debugging and optimization:

| Parameter | Example | Purpose |
|-----------|---------|---------|

## JSON Schema for ManpLabMetadata

### Field Definitions: Fractal Identification

**FractalFamily** (string, required)
- Browser category/folder name where fractal appears
- User-facing grouping name
- Examples: `"Classic Escape-Time"`, `"Newton Method"`, `"Historical Fractals"`, `"Special & Exotic"`
- Purpose: Helps users understand the mathematical family/category
- UI Display: Show as "Fractal Family" (with space) in metadata viewers

**FractalName** (string, required)
- Display name of the specific fractal as shown in the browser
- Human-readable, descriptive name
- Examples: `"Mandelbrot Set"`, `"Burning Ship"`, `"Newton (z³-1)"`, `"Pickover Biomorphs"`
- Purpose: Clear identification for users browsing image metadata

**FractalType** (string, required)
- Internal identifier matching the native fractal registry key
- Technical name used in code
- Examples: `"Mandelbrot"`, `"BurningShip"`, `"Newton3"`, `"Biomorphs"`
- Purpose: Exact matching for programmatic reproduction

**Example Relationship:**
```json
{
  "FractalFamily": "Classic Escape-Time",
  "FractalName": "Burning Ship",
  "FractalType": "BurningShip"
}
```

Another example:
```json
{
  "FractalFamily": "Newton Method",
  "FractalName": "Newton (z³-1)",
  "FractalType": "Newton3"
}
```

### Field Name Mapping: UI Labels to JSON Properties

This table shows how UI labels and clipboard text map to JSON property names in the metadata:

| UI Label / Clipboard Field | JSON Property Name | Code Property Name | Notes |
|---------------------------|-------------------|-------------------|-------|
| **Fractal:** | `FractalName` | `FractalDescriptor.DisplayName` | User-facing display name |
| **Fractal Family** | `FractalFamily` | `FractalDescriptor.Category` | Browser folder grouping |
| *Internal ID* | `FractalType` | `FractalDescriptor.Name` | Registry key (not shown in UI) |
| **Center:** | `CenterX`, `CenterY` | `CenterX`, `CenterY` | Split into two properties |
| **Zoom:** | `ZoomFactor` | `Zoom` | Magnification level |
| **View Width:** | `ViewWidth` | *(calculated)* | Complex plane width = ImageWidth / (Zoom × scale) |
| **View Height:** | `ViewHeight` | *(calculated)* | Complex plane height = ImageHeight / (Zoom × scale) |
| **Max Iterations:** | `MaxIterations` | `MaxIterations` | Direct match |
| **Auto-scale Iterations:** | `AutoScaleIterations` | `AutoScaleIterations` | Direct match |
| **Resolution:** (WxH) | `ResolutionWidth`, `ResolutionHeight` | `ImageWidth`, `ImageHeight` | Split into two properties |
| **Resolution:** (MP) | `ResolutionMegapixels` | *(calculated)* | (Width × Height) / 1,000,000 |
| **Render Time:** | `RenderTimeSeconds` | `ComputeTimeMs` / 1000 | Stored as seconds in JSON |
| **Palette:** | `PaletteName` | `ColorPalette` | Color scheme name |
| *Escape %* | `EscapePercentage` | *(from render stats)* | Percentage of pixels that escaped |
| **Personal Notes** | `UserNotes` | *(from Properties panel)* | Multi-line text for tagging/special projects |

**Key Principles:**
- JSON property names are descriptive and self-documenting
- UI labels may be shortened (e.g., "Zoom:" becomes `ZoomFactor`)
- Compound values are split into separate properties (e.g., Center → CenterX + CenterY)
- Derived values are calculated from base parameters (ViewWidth, ViewHeight, ResolutionMegapixels)
- Code property names may differ; use `JsonPropertyName` attribute when mapping

## Implementation Recommendations

### 1. Writing Metadata

#### PNG Implementation (C# with Windows.Graphics.Imaging)

```csharp
// Create encoder
var encoder = await BitmapEncoder.CreateAsync(BitmapEncoder.PngEncoderId, stream);

// Set pixel data
encoder.SetPixelData(...);

// Prepare metadata object
var metadata = new FractalMetadata
{
    Software = "ManpLab",
    Version = "1.0.0",
    SourceCode = "https://github.com/markhassellsmith/ManpLab",
    License = "MIT",
    FractalFamily = "Classic Escape-Time",
    FractalName = "Mandelbrot Set",
    FractalType = "Mandelbrot",
    CenterX = -0.5,
    CenterY = 0.0,
    Zoom = 1.0,
    MaxIterations = 512,
    // ... other properties
};

// Serialize to JSON
var jsonMetadata = JsonSerializer.Serialize(metadata, 
    new JsonSerializerOptions { WriteIndented = false });

// Write primary JSON blob and attribution properties
var properties = encoder.BitmapProperties;
await properties.SetPropertiesAsync(new[]
{
    new BitmapPropertySet
    {
        { "/tEXt/ManpLabMetadata", new BitmapTypedValue(jsonMetadata, PropertyType.String) }
    },
    new BitmapPropertySet
    {
        { "/tEXt/Software", new BitmapTypedValue($"ManpLab v{metadata.Version}", PropertyType.String) }
    },
    new BitmapPropertySet
    {
        { "/tEXt/Source", new BitmapTypedValue(metadata.SourceCode, PropertyType.String) }
    },
    new BitmapPropertySet
    {
        { "/tEXt/Creation Time", new BitmapTypedValue(DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss"), PropertyType.String) }
    }
});

await encoder.FlushAsync();
```

**Important Notes**:
- Each property requires its own `BitmapPropertySet`
- Use `try-catch` for each `SetPropertiesAsync` call (some properties may fail silently)
- PNG tEXt chunks are case-sensitive
- **Always include Software and Source for proper attribution**

#### JPEG Implementation (C# with Windows.Graphics.Imaging)

```csharp
// Create encoder
var encoder = await BitmapEncoder.CreateAsync(BitmapEncoder.JpegEncoderId, stream);

// Set pixel data
encoder.SetPixelData(...);

// Serialize metadata
var jsonMetadata = JsonSerializer.Serialize(metadata, 
    new JsonSerializerOptions { WriteIndented = false });

// EXIF UserComment requires character code prefix
var userComment = "ASCII\0\0\0" + jsonMetadata;

// Write EXIF tags with attribution
var properties = encoder.BitmapProperties;
await properties.SetPropertiesAsync(new[]
{
    new BitmapPropertySet
    {
        { "/app1/ifd/{ushort=305}", new BitmapTypedValue($"ManpLab v{metadata.Version}", PropertyType.String) }
    },
    new BitmapPropertySet
    {
        { "/app1/ifd/{ushort=270}", new BitmapTypedValue(
            $"Mandelbrot set at (-0.5, 0.0) - {metadata.SourceCode}", PropertyType.String) }
    },
    new BitmapPropertySet
    {
        { "/app1/ifd/exif/{ushort=37510}", new BitmapTypedValue(userComment, PropertyType.String) }
    }
});

await encoder.FlushAsync();
```

### 2. Reading Metadata

#### PNG Implementation

```csharp
// Open decoder
var decoder = await BitmapDecoder.CreateAsync(stream);

// Try to read ManpLabMetadata JSON blob
try
{
    var properties = await decoder.BitmapProperties.GetPropertiesAsync(
        new[] { "/tEXt/ManpLabMetadata" });

    if (properties.TryGetValue("/tEXt/ManpLabMetadata", out var value))
    {
        var json = value.Value.ToString();
        var metadata = JsonSerializer.Deserialize<FractalMetadata>(json);
        // Use metadata to restore fractal parameters
    }
}
catch
{
    // Fallback: try to read individual properties
    // Read /tEXt/CenterX, /tEXt/CenterY, etc.
}
```

#### JPEG Implementation

```csharp
// Open decoder
var decoder = await BitmapDecoder.CreateAsync(stream);

// Try to read EXIF UserComment
try
{
    var properties = await decoder.BitmapProperties.GetPropertiesAsync(
        new[] { "/app1/ifd/exif/{ushort=37510}" });

    if (properties.TryGetValue("/app1/ifd/exif/{ushort=37510}", out var value))
    {
        var userComment = value.Value.ToString();

        // Strip character code prefix (first 8 bytes)
        if (userComment.StartsWith("ASCII"))
        {
            var json = userComment.Substring(8);
            var metadata = JsonSerializer.Deserialize<FractalMetadata>(json);
        }
    }
}
catch
{
    // Fallback: try reading standard EXIF tags
}
```

### 3. Validation and Error Handling

**Recommended Validation Rules**:

1. **Always validate JSON deserialization**
   - Check schema version compatibility
   - Provide defaults for missing fields
   - Reject malformed JSON gracefully

2. **Validate mathematical constraints**
   - CenterX, CenterY within reasonable bounds (-2 to 2 for Mandelbrot)
   - Zoom > 0
   - MaxIterations > 0
   - ImageWidth, ImageHeight > 0

3. **Handle version differences**
   - Store schema version in metadata
   - Implement migration logic for old versions
   - Graceful degradation for unknown properties

Example:
```csharp
public FractalMetadata LoadMetadata(string json)
{
    try
    {
        var metadata = JsonSerializer.Deserialize<FractalMetadata>(json);

        // Validate
        if (metadata.Zoom <= 0)
            throw new InvalidDataException("Invalid zoom value");

        if (metadata.MaxIterations <= 0)
            throw new InvalidDataException("Invalid iteration count");

        // Check version compatibility
        if (!IsCompatibleVersion(metadata.Version))
        {
            // Attempt migration or warn user
        }

        return metadata;
    }
    catch (JsonException ex)
    {
        // Log error and return null or default
        return null;
    }
}
```

## Best Practices Summary

### DO:
✅ **Always write JSON blob first** - Contains complete information
✅ **Use minified JSON** - Reduces file size
✅ **Preserve high precision** - Use 15-17 digits for doubles
✅ **Include version number** - Enables future migration
✅ **Write timestamp** - Documents creation date
✅ **Test read-back** - Verify metadata survives save/load cycle
✅ **Handle errors gracefully** - Some properties may fail to write
✅ **Use ISO 8601 for timestamps** - Unambiguous date format
✅ **Store null for unused fields** - Explicit absence

### DON'T:
❌ **Don't rely on individual properties alone** - Incomplete for reproduction
❌ **Don't use whitespace in JSON** - Wastes space
❌ **Don't assume all properties will write** - Some may fail silently
❌ **Don't store sensitive information** - Metadata is unencrypted
❌ **Don't exceed 79 characters for PNG tEXt keywords** - Standard limit
❌ **Don't use non-ASCII characters without iTXt** - Standard tEXt is Latin-1

### Why Attribution Matters

Proper attribution in image metadata:
- ✅ Credits the ManpLab project and its contributors
- ✅ Helps users discover the tool that created the image

- ✅ Enables users to report issues or request features

### User vs. Software Attribution

**Distinguish between:**

1. **Software Attribution** (ManpLab and its developers)
   - `/tEXt/Software` = `"ManpLab v1.0.0"`
   - `/tEXt/Source` = `"https://github.com/markhassellsmith/ManpLab"`
   - JSON: `"Software"`, `"Version"`, `"SourceCode"`, `"License"`

2. **User Attribution** (person who created this specific render)
   - `/tEXt/Author` = User's name (optional, user choice)
   - `/tEXt/Copyright` = User's copyright (optional)
   - JSON: `"Author"`, `"Copyright"`, `"UserNotes"`

### Implementation Helper Function

```csharp
public static class MetadataAttribution
{
    public const string SOFTWARE_NAME = "ManpLab";
    public const string SOURCE_URL = "https://github.com/markhassellsmith/ManpLab";
    public const string LICENSE = "MIT";

    public static string GetSoftwareString(string version)
        => $"{SOFTWARE_NAME} v{version}";

    public static string GetAttributionComment()
        => $"Generated by {SOFTWARE_NAME} - Open source fractal explorer\n{SOURCE_URL}";

    public static async Task AddAttributionPropertiesPNG(
        BitmapPropertySet properties,
        string version,
        string? userAuthor = null,
        string? userCopyright = null)
    {
        await properties.SetPropertiesAsync(new[]
        {
            new BitmapPropertySet
            {
                { "/tEXt/Software", new BitmapTypedValue(GetSoftwareString(version), PropertyType.String) }
            },
            new BitmapPropertySet
            {
                { "/tEXt/Source", new BitmapTypedValue(SOURCE_URL, PropertyType.String) }
            }
        });

        // Add optional user attribution
        if (!string.IsNullOrEmpty(userAuthor))
        {
            await properties.SetPropertiesAsync(new[]
            {
                new BitmapPropertySet
                {
                    { "/tEXt/Author", new BitmapTypedValue(userAuthor, PropertyType.String) }
                }
            });
        }

        if (!string.IsNullOrEmpty(userCopyright))
        {
            await properties.SetPropertiesAsync(new[]
            {
                new BitmapPropertySet
                {
                    { "/tEXt/Copyright", new BitmapTypedValue(userCopyright, PropertyType.String) }
                }
            });
        }
    }
}
```

## Appendix: Derived Field Calculations

### Overview

Several metadata fields are **derived** from base parameters rather than directly stored in the application's state. This section documents the exact formulas for calculating these values.

---

### ViewWidth and ViewHeight

**Purpose**: Represent the dimensions of the visible region in the complex plane (mathematical coordinates).

**Formula**:
```
ViewWidth  = ResolutionWidth  / (ZoomFactor × PixelsPerUnit)
ViewHeight = ResolutionHeight / (ZoomFactor × PixelsPerUnit)
```

Where:
- `ResolutionWidth`, `ResolutionHeight`: Image dimensions in pixels
- `ZoomFactor`: Current magnification level (1.0 = base zoom)
- `PixelsPerUnit`: Scale factor mapping complex plane units to pixels (typically calculated to maintain aspect ratio)

**Alternative Formula** (if using viewport bounds):
```
ViewWidth  = abs(MaxX - MinX)
ViewHeight = abs(MaxY - MinY)
```

Where `MinX`, `MaxX`, `MinY`, `MaxY` are the complex plane boundaries of the viewport.

**Example**:
```
ResolutionWidth   = 1920 pixels
ResolutionHeight  = 1080 pixels
ZoomFactor        = 214.67
PixelsPerUnit     = 384 (calculated from base scale)

ViewWidth  = 1920 / (214.67 × 384) ≈ 0.0139746244
ViewHeight = 1080 / (214.67 × 384) ≈ 0.0078607262
```

---

### ResolutionMegapixels

**Purpose**: Convenient single-value representation of image resolution.

**Formula**:
```
ResolutionMegapixels = (ResolutionWidth × ResolutionHeight) / 1,000,000
```

**Example**:
```
1920 × 1080 / 1,000,000 = 2.07 MP
3840 × 2160 / 1,000,000 = 8.29 MP
```

---

### RenderTimeSeconds

**Purpose**: Human-readable render duration in seconds.

**Formula**:
```
RenderTimeSeconds = ComputeTimeMs / 1000
```

Where `ComputeTimeMs` is the render time in milliseconds (typically from `Stopwatch.ElapsedMilliseconds`).

**Example**:
```
ComputeTimeMs     = 3336.7628
RenderTimeSeconds = 3.3367628
```

**Note**: Store with sufficient precision (3-4 decimal places) for accurate performance analysis.

---

### EscapePercentage

**Purpose**: Indicates what fraction of pixels reached the iteration escape threshold (vs. those that remained bounded).

**Formula**:
```
EscapePercentage = (EscapedPixels / TotalPixels) × 100
```

Where:
- `EscapedPixels`: Count of pixels where iteration count < MaxIterations
- `TotalPixels`: ResolutionWidth × ResolutionHeight

**Example**:
```
TotalPixels    = 1920 × 1080 = 2,073,600
EscapedPixels  = 1,810,224
EscapePercentage = (1,810,224 / 2,073,600) × 100 ≈ 87.3%
```

**Interpretation**:
- **High escape %** (>90%): Simple region, mostly exterior of the set
- **Medium escape %** (50-90%): Boundary region with detail
- **Low escape %** (<50%): Interior or deep detail regions

---

### AutoScaleIterations

**Purpose**: Boolean flag indicating whether `MaxIterations` was automatically adjusted based on zoom level.

**Logic**:
```
if (UserEnabledAutoScale && ZoomFactor > AutoScaleThreshold)
    AutoScaleIterations = true
    MaxIterations = CalculateAutoScaledIterations(ZoomFactor)
else
    AutoScaleIterations = false
    MaxIterations = UserSetValue
```

**Note**: When `AutoScaleIterations` is true, the stored `MaxIterations` value is the *calculated* value, not the user's base setting. Consider also storing `BaseMaxIterations` if you need to preserve the user's original choice.

## Conclusion

The recommended strategy balances:
- **Completeness**: JSON blob ensures all parameters are preserved
- **Compatibility**: Standard properties work with any viewer
- **Simplicity**: Implementation is straightforward in .NET
- **Extensibility**: Easy to add new fields without breaking old readers
- **Reliability**: PNG tEXt chunks are well-supported and stable

**Primary Recommendation**: Use PNG with `/tEXt/ManpLabMetadata` JSON blob plus standard identification properties. This provides the best combination of features for fractal applications.

**Secondary Option**: Use JPEG with EXIF UserComment for smaller file sizes when lossy compression is acceptable.
